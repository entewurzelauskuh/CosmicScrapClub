# VFX Phase B-3a — Cube-Death Enhancement — Design

**Date:** 2026-07-27
**Branch:** `vfx/b3a-cube-death`
**Status:** approved (design), pending implementation plan

## Context

`CubeDeath` (in `CubeFly.Core`) currently plays a "logically complete but
visually flat" death: at 0 HP a cube detaches from the construct, disables its
colliders, and drifts outward at 2 u/s for 2 s before despawning. Phase B-3
(destruction + crash) is sliced into **B-3a / B-3b / B-3c**; this is **B-3a —
the cube-death enhancement** from `docs/vfx_pass_ideas.md` §5: add a one-frame
flash, a spark burst, particle debris, and a flame/smoke trail so a dying cube
*reads* as destroyed rather than just floating away.

B-3b (sustained smoke + red emissive flicker on <25%-HP cubes) and B-3c
(camera shake on crash + nearby detonation) are **out of scope** here — separate
slices, separate branches.

This builds directly on the B-2 desert-verify fix: the additive particle blend
(`_Blend = 2`) is now correct, so additive flash/spark bloom cleanly instead of
rendering muddy premultiply.

## Goals

- A dying cube produces, at the moment of death: a brief bright flash, a radial
  spark burst, ~4 scattered debris chunks, and a lingering flame/smoke trail
  that tracks the drifting wreck for the 2 s drift.
- Fires for **every** death path (weapon kill, crash, eject) and for **any**
  dying cube (player construct, world targets, turret pyramids) — they all
  funnel through `CubeDeath.BeginDeath`.
- Cheap: particle-only, no rigidbodies, no per-frame cost on living cubes, no
  spike when several cubes die in one frame.
- Independently toggleable from the Settings → Debug tab, matching the B-1/B-2
  pattern.
- Decoupled: `CubeDeath` stays in `Core` with no hard dependency on VFX assets —
  unconfigured scenes (menus) simply show the existing drift with no new VFX.

## Non-goals

- Low-HP sustained smoke / emissive flicker (B-3b).
- Camera shake (B-3c).
- Alpha-cube cinematic death sequence (Phase D — the alpha still skips
  `CubeDeath` entirely and is owned by end-of-run).
- Physics-driven debris (explicitly rejected in brainstorm — particle debris
  chosen for cost/robustness).
- Shield-aware hit sparks (a separate §5 idea, not this slice).

## Hook point

`CubeDeath.BeginDeath(Vector3 outwardOrigin)` — after the existing alpha/`_dying`
guards and after `ComputeDriftDirection`, before `StartCoroutine(DriftAndDespawn)`.
The drift direction is already computed there and is exactly the axis we bias
debris + orient the burst along.

The alpha-cube early-return (`if (CompareTag("AlphaCube")) return;`) sits *above*
the hook, so the alpha never triggers B-3a VFX — correct, its death is Phase D.

## Assets (procedurally generated by `VfxAssetsInstaller`)

Mirrors how B-1/B-2 assets are generated (procedural textures + URP
`Particles/Unlit` materials + `PrefabUtility.SaveAsPrefabAsset`, stable GUIDs).

1. **`CubeDeathBurst.prefab`** — a one-shot ParticleSystem instantiated at the
   cube's position, rotated so local +Z = drift direction, root
   `main.stopAction = Destroy` (self-cleans; no despawn script). Three
   sub-systems under one root:
   - **Flash** — 1 particle, bright **additive** disc (reuse the `Glow_64` /
     muzzle-disc texture + an additive material), start size ≈ cube size,
     lifetime ≈ 0.08 s. Bloom (desert threshold 1.1) halos it into the
     "one-frame white flash".
   - **Spark** — burst of ≈ 20 small **additive** spark streaks (reuse the
     tracer-stripe / spark look), spherical emission, lifetime ≈ 0.3 s, HDR
     warm-white start colour.
   - **Debris** — burst of ≈ 4 **mesh particles** (unit cube mesh), an
     **opaque** unlit/lit dark-metal material (`CubeDebrisMat`), cone emission
     along local +Z (drift dir) with spread, `gravityModifier > 0`, random
     rotation + rotation-velocity, start size ≈ 0.15–0.25, lifetime ≈ 2 s,
     size/alpha unaffected (they're solid chunks, not glow).
2. **`CubeDebrisMat`** — opaque URP `Unlit` (or `Lit`) material, dark rust/metal
   tint, for the debris mesh particles. (New; not additive.)
3. **Flame/smoke trail** — no new prefab; a `TrailRenderer` is added to the
   dying cube at runtime in `BeginDeath`, using **`RocketSmokeTrailMat`**
   (reused to start; swap to a dedicated `CubeDeathTrailMat` only if it reads
   wrong). Grey-white, width tapering to 0, `time` ≈ 2 s to match the drift,
   detached-to-linger on despawn via the existing `LingeringTrail` helper so the
   tail fades instead of popping.

## Runtime wiring

Mirrors B-2's `ProjectileHit.ConfigureImpactPrefabs`:

- `CubeDeath` gains two static fields (`BurstPrefab`, `TrailMaterial`) and a
  static `ConfigureVfx(GameObject burst, Material trail)` setter.
- `FlyController` gains two serialized fields (`cubeDeathBurstPrefab`,
  `cubeDeathTrailMaterial`, assigned by `VfxAssetsInstaller`) and calls
  `CubeDeath.ConfigureVfx(...)` once in `Awake` (alongside the existing
  `ProjectileHit.ConfigureImpactPrefabs`).
- In `BeginDeath`, after computing `driftDir`:
  - If `VfxSettings.CubeDeathBurst && BurstPrefab != null`:
    `Instantiate(BurstPrefab, transform.position, Quaternion.LookRotation(driftDir))`.
  - If `VfxSettings.CubeDeathTrail && TrailMaterial != null`: add a
    `TrailRenderer` to the cube, configured + material set, and register it with
    `LingeringTrail` so it detaches and fades when the cube despawns.
- Null-safe throughout: a scene that never calls `ConfigureVfx` (menus) or a
  disabled toggle → no VFX, existing drift unchanged.

## Settings toggles

Two new `VfxSettings` keys + two Debug-tab rows (same pattern as the 8 B-2
toggles), default **on**:

| Key | Property | Covers |
| --- | --- | --- |
| `VfxCubeDeathBurst` | `CubeDeathBurst` | flash + spark + debris (the burst prefab) |
| `VfxCubeDeathTrail` | `CubeDeathTrail` | the flame/smoke `TrailRenderer` |

Debug-tab tooltip text sourced from `docs/vfx_pass_ideas.md` §5 (shortened).

## Tuning defaults (starting points, tuned in Play)

| Param | Value |
| --- | --- |
| Flash lifetime / size | 0.08 s / ≈ cube size |
| Spark count / lifetime | ≈ 20 / 0.3 s |
| Debris count / size / lifetime | ≈ 4 / 0.15–0.25 / 2 s |
| Debris gravity modifier | ≈ 0.5–1.0 |
| Trail time / width | 2 s / ≈ 0.3 → 0 |

## Edge cases / risks

- **Multi-cube deaths in one frame** (e.g. a rocket or crash killing a cluster):
  each spawns one burst prefab + one trail. Particle-only + `stopAction=Destroy`
  keeps this bounded; watch for a spike in the Play gate. No pooling for now
  (matches B-2 impact VFX); revisit only if the profiler flags it.
- **World targets / turrets** dying: they run `BeginDeath` too and correctly get
  the VFX (shooting a target should shatter). No `PlacedCubeData` needed.
- **`CubeDeath` is in `Core`; `VfxSettings` is in `Core`** — same assembly, so
  the toggle read is a clean reference. The prefab/material refs arrive via the
  static `ConfigureVfx` (no Core→prefab asset dependency).
- **Trail on a detached, collider-disabled cube**: fine — `TrailRenderer` needs
  only the transform, which keeps moving under the drift coroutine.
- **Debris mesh particles** need the ParticleSystemRenderer in `Mesh` render
  mode with the cube mesh assigned — verify the installer sets this (B-1/B-2
  used Billboard/Stretch; Mesh mode is new here).

## Verification & gate

Play-mode fly + shoot in the desert FlyScene (maintainer gate, per project VFX
practice):
- Shoot a target cube → flash + spark + debris + trail fire and read against the
  sand; the burst blooms (additive) without blowing out.
- Crash into a cube → same VFX via the crash death path.
- Destroy a cluster (rocket) → no visible perf spike; multiple bursts fine.
- Toggle `CubeDeathBurst` / `CubeDeathTrail` off in Settings → Debug → each
  effect disappears independently; cube still drifts + despawns.
- Menu scenes / direct-Play sanity: no errors from unconfigured `CubeDeath`.

## Implementation outline (for writing-plans)

1. `VfxSettings` — add the 2 keys + properties.
2. `SettingsMenu` Debug tab — add the 2 toggle rows + tooltips.
3. `VfxAssetsInstaller` — generate `CubeDebrisMat`, the `CubeDeathBurst.prefab`
   (flash + spark + debris sub-systems, Mesh-mode debris), and wire the new
   `FlyController` serialized refs.
4. `CubeDeath` — static `BurstPrefab`/`TrailMaterial` + `ConfigureVfx`; spawn
   burst + attach lingering trail in `BeginDeath` (toggle- and null-guarded).
5. `FlyController` — serialized refs + `CubeDeath.ConfigureVfx(...)` in `Awake`.
6. Compile-check (`read_console`), then Play-mode gate + tune.
7. Land via the B-3a PR (fast-forward), then proceed to B-3b.
